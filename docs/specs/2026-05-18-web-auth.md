# Web auth pages (login + register + protected routes)

- **Date**: 2026-05-18
- **Status**: Approved
- **Linked issue**: #4
- **Linked PR**: #4

## 1. Context

The API delivered in PR #3 exposes `/api/auth/register`, `/api/auth/login` and
`/api/me` behind JWT + role gating. This PR ships the matching public web
pages so a user can self-register or log in and be redirected to the area
appropriate for their role (admin → `/admin/upload`, user → `/extrato`).

The UI is built with shadcn/ui (Radix under the hood) on Tailwind, with
form state owned by react-hook-form and validation by Zod schemas that
intentionally mirror the API ones — both consume types from
`@nex/shared` to stay in sync.

Authenticated state lives in a Zustand store persisted to `localStorage`.
TanStack Query is set up here so subsequent feature PRs can drop their
`useQuery` calls in without re-bootstrapping the cache.

## 2. Requirements

### Functional

- [ ] `/login` form: email + password → `POST /api/auth/login` → store
  token + user → redirect by role.
- [ ] `/register` form: name + email + CPF + password + consent
  checkbox → `POST /api/auth/register` → store token + user → redirect.
- [ ] CPF input is masked (`000.000.000-00`) and client-side validated.
- [ ] Header errors mapped from API response codes
  (`conflict`, `unauthorized`, `validation_failed`).
- [ ] `ProtectedRoute` redirects unauthenticated users to `/login`.
- [ ] `RoleRoute` redirects users with the wrong role to `/`.
- [ ] Auth store survives reload (localStorage).
- [ ] Logout clears storage and redirects to `/login`.

### Non-functional

- [ ] Forms accessible (labels, error announcements, autofocus).
- [ ] Mobile-friendly (min-width tested at 320px).
- [ ] All copy in pt-BR (UI), code in English.
- [ ] No CPF in `console.log`; no token in URLs or query strings.

